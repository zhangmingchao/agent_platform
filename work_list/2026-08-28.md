## 1. 工作流人工确认节点

### 功能描述

工作流画布新增“人工确认”节点。工作流执行到该节点时会保存当前执行状态并暂停，等待用户进行批准或拒绝。

批准后从人工确认节点的下一个节点继续执行，不会重复运行前面的 Agent；拒绝后结束本次工作流。

### 主要改动

- 前端工作流画布新增人工确认节点和节点配置面板。
- 支持配置节点名称和审批提示语。
- 工作流运行页面新增审批意见、批准、拒绝操作。
- 后端增加工作流审批接口：

```text
POST /api/workflows/runs/{run_id}/approval
```

- 新增工作流状态：
  - `waiting_approval`
  - `approved`
  - `rejected`
- 使用 `multi_agent_runs.context_json` 保存恢复节点、当前输入和步骤序号。
- 新增 SSE 事件：
  - `approval_required`
  - `approval_decided`
  - `rejected`
- SSE 支持通过 `after` 参数从指定事件之后恢复订阅，避免批准后重复读取旧的待审批事件。

### 影响范围

- 工作流创建和编辑画布。
- 工作流后台执行状态机。
- 工作流运行详情和 SSE 事件订阅。
- 工作流步骤状态展示。

## 2. Agent 提示词模板变量

### 功能描述

Agent 系统提示词现在支持以下变量语法：

```text
{{variable_name}}
```

例如：

```text
你是一名{{role}}，请使用{{language}}回答{{username}}的问题：
{{user_input}}
```

Agent 可以配置自定义默认变量：

```json
{
  "role": "售后客服",
  "language": "中文"
}
```

### 内置运行时变量

单 Agent 对话支持：

- `user_input`
- `username`
- `user_id`
- `session_id`
- `current_date`

工作流 Agent 节点额外支持：

- `workflow_input`
- `workflow_id`
- `run_id`
- `step_order`
- `role`
- `instruction`

运行时变量会覆盖同名默认变量。未提供值的模板变量会保留原始形式，便于发现配置遗漏。

### 实现方式

- 新增 `agents.prompt_variables` JSON 字段。
- 使用受限正则进行变量替换。
- 不执行 Python、函数、循环或条件表达式，避免模板执行任意代码。
- 单 Agent 对话和工作流节点在每次运行前分别构造运行时变量并渲染系统提示词。

### 影响范围

- Agent 创建和编辑页面。
- 单 Agent 对话初始化。
- 多 Agent 工作流节点初始化。
- Agent 配置的数据库读写。

## 3. Agent 结构化输出 JSON Schema

### 功能描述

Agent 可以选择启用结构化输出，并配置 JSON Schema。模型生成结束后，系统会解析完整 JSON，并使用 JSON Schema Draft 2020-12 进行校验。

SSE 流式 Token 保持不变，结构化结果只会在完整内容生成并校验成功后发送。

### 执行流程

```text
渲染系统提示词
  -> 追加 JSON Schema 输出要求
  -> LLM 流式生成
  -> 合并最终回答
  -> JSON 解析
  -> JSON Schema 校验
  -> 持久化结构化结果
  -> 发送 structured_result SSE 事件
```

### 主要改动

- 新增 `agents.output_schema` JSON 字段。
- 新增依赖 `jsonschema>=4.20.0`。
- 支持校验 Schema 本身是否合法。
- 支持解析纯 JSON 和 `json` Markdown 代码块。
- 输出不符合 Schema 时返回明确错误，不将无效数据作为结构化结果保存。
- 新增 SSE 事件：`structured_result`。
- 对话页面和工作流运行页面新增结构化结果展示。

### 数据库改动

```text
agents.prompt_variables
agents.output_schema
chat_messages.structured_content
multi_agent_run_steps.output_json
```

数据库迁移已经在本地执行，并确认以上字段存在。

### 对两种运行模式的影响

#### 单 Agent 对话

- 普通文本继续通过 SSE 实时显示。
- 校验后的结果保存到 `chat_messages.structured_content`。
- 历史消息接口返回结构化内容。

#### 多 Agent 工作流

- 每个启用 Schema 的 Agent 节点独立校验输出。
- 校验结果保存到 `multi_agent_run_steps.output_json`。
- 下游节点仍能接收该 Agent 的最终 JSON 文本。
- 工作流 Trace、节点错误和 SSE 状态保持原有处理方式。

## 4. 最小 LangChain Agent Demo

### 功能描述

新增一个独立、简化的 LangChain Agent 示例，用于展示大模型如何自行选择并调用 Tool。

示例包含两个模拟 Tool：

- `query_weather`：模拟查询城市天气。
- `query_order`：模拟查询订单状态。

### 示例特点

- 使用 `ChatOpenAI` 连接 OpenAI 兼容接口。
- 使用 LangChain `create_agent` 创建 Agent。
- 使用 `@tool` 声明工具。
- 支持简单的命令行连续对话历史。
- 不依赖当前项目的数据库、Redis、FastAPI 或沙箱服务。
- 新增 `run_agent()`，真实调用大模型并统一返回最终答案、执行步骤和完整消息历史。
- 显式处理 `AIMessage.tool_calls`、`ToolMessage` 和最终 `AIMessage`，可以观察完整 Tool Calling 循环。
- 增加模型调用异常捕获位置，便于后续接入统一错误响应、Trace 或重试。

### 相关文件

- `backend/demos/simple_langchain_agent.py`

### 运行方式

```bash
export LLM_API_KEY="你的 API Key"
export LLM_BASE_URL="https://api.deepseek.com"
export LLM_MODEL="deepseek-chat"

backend/.venv-langchan/bin/python backend/demos/simple_langchain_agent.py
```
