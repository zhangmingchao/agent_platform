## 认证凭据加密与高风险接口限流

### work_list

1. 使用 Argon2id 替换用户密码明文存储，并兼容历史明文首次登录自动迁移。
2. 使用 AES-256-GCM 加密模型 API Key，并兼容历史明文首次读取自动迁移。
3. 基于 Redis Lua 实现分布式固定窗口限流和统一的 429、Retry-After 响应。
4. 为登录、注册、模型测试、MCP 调用、聊天、工作流运行与审批、Runtime 上传和代码执行接入限流。
5. 禁止初始化脚本继续创建默认弱口令账号，扩展密码哈希字段长度。
6. 增加安全功能单元测试、部署配置说明和迁移文档。
7. 执行语法检查、安全专项测试、现有后端回归测试和差异格式检查。

### 实现方案

- 密码只保存不可逆 Argon2id 哈希；历史明文仅用于一次兼容验证，成功后立即覆盖为哈希。
- 模型 API Key 使用部署环境提供的独立 256 位主密钥进行认证加密，业务读取后只在内存中短暂保留明文。
- 限流状态存储在 Redis，使多个 API 实例共享计数；Redis 不可用时高风险操作采用失败关闭策略。

### 实现结果

- 新注册、修改密码使用 Argon2id；历史明文密码在首次成功登录后自动升级。
- 模型 API Key 使用 AES-256-GCM 保存；历史明文在首次业务读取时自动升级，API 始终不返回 Key。
- 登录、注册及模型、MCP、聊天、工作流、Runtime 高风险入口已接入 Redis 分布式限流。
- 数据库初始化不再创建默认弱口令用户，并自动扩展密码哈希和 API Key 密文字段。
- 安全专项 9 项测试通过，后端完整 73 项测试通过；`compileall` 和 `git diff --check` 通过。
