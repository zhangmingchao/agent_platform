# 2026-09-20 工作记录

## 目标

借鉴 DeepSeek Harness 的沙箱与权限模型，为 Agent Platform 增加第一版工具权限预设和执行前决策能力。

## 实现方案

1. 新增权限模型实体，拆分沙箱模式、审批策略、权限预设、工具风险等级和执行决策。
2. 新增权限决策服务，按 Agent 默认权限预设判断工具调用是否允许继续。
3. 为 Agent 增加 `permission_preset` 字段，默认值为 `standard`。
4. 为会话表预留 `permission_preset`、`sandbox_mode`、`approval_policy` 字段，支持后续会话级覆盖。
5. 将 `ExecutePython` 接入统一权限网关，安全模式拒绝中风险 Runtime 执行，标准/自动/开发者模式允许在当前沙箱边界内执行。
6. 前端 Agent 表单增加权限预设选择，Agent 列表展示当前预设。
7. 工具返回值增加 `permission` 审计信息，便于 Trace 和调试查看本次决策。
8. 增加 Tool Execution Pipeline，对 Skill、Runtime、MCP 等 LangChain 工具统一执行前权限决策和拒绝返回。
9. 增加 Agent Loop 生命周期事件模型，在流式执行中输出 turn、step、LLM 和 tool 阶段事件。
10. 在聊天页增加当前运行态观察面板，展示执行时间线、Trace 分组和 Agent 调试状态。

## 插件化 LLM Adapter 实现方案

1. 新增 LLM Adapter 强类型实体，使用 `dataclass` 描述适配器能力、构建参数和对外展示信息。
2. 定义 `LlmAdapter` 协议接口，约束所有供应商适配器都通过 `build_chat_model` 构建 LangChain Chat Model。
3. 新增 OpenAI 兼容协议适配器，当前覆盖 OpenAI、DeepSeek、Qwen 和兼容网关。
4. 新增 Adapter 注册表，统一处理 provider 规范化、内置供应商查询和未知 provider 回退。
5. 改造 Agent 工厂，让模型创建逻辑从直接依赖 `ChatOpenAI` 变为通过 provider 选择 Adapter。
6. 改造模型连接测试，让测试流程复用同一套 Adapter 注册表，避免运行路径和测试路径分叉。
7. 新增 `/api/models/adapters` 接口，供前端或 SDK 查询后端当前可用的适配器能力。

## 平台底座四项升级实现方案

1. Session Event Append-Only 日志持久化：新增不可变事件实体、写入服务和 `session_events` 表，Agent Loop 与 Tool Pipeline 只追加事件，不覆盖历史事件。
2. Tool Execution Pipeline 多阶段化：将工具执行拆成参数校验、权限决策、执行前记录、真实执行、执行后审计和错误事件阶段。
3. 权限模型细化：在权限预设中增加工具允许/拒绝、可读路径、可写路径、网络策略、允许域名和阻断命令关键字，并将规则快照写入权限决策。
