# 2026-09-01 开发记录

## 单 Agent 流式文本按轮次分类

- 删除依赖全局 `has_seen_tool` 的启发式分类，改为按 LangChain `run_id` 管理 LLM 轮次。
- 新增 `llm_round_start`、`pending_text_delta`、`llm_round_classified` 事件。
- 流式 Token 先实时进入“处理中”，轮次结束后再归类为执行说明或正式回答。
- 工具事件升级为 `tool_started/tool_completed`，通过 `tool_run_id` 精确匹配。

## 执行说明展示与持久化

- `chat_messages` 新增 `reasoning_content`，与正式回答 `content` 分离保存。
- 历史消息中的执行说明默认折叠，用户可点击展开。
- 执行说明采用中性灰，正式回答保持主文字色。
- 执行说明不加入后续 LLM 历史上下文，避免污染会话记忆。

## 影响范围

- 后端 SSE 协议已升级，前端同步切换到新事件。
- 服务启动时数据库初始化自动添加 `reasoning_content` 字段。
- 结构化输出只校验正式回答，不处理执行说明。

## Python 风格结构化输出描述

- Agent 创建/编辑页新增“Python 模型”和“JSON Schema”双模式，默认使用 Python 模型模式。
- 新增安全 AST 转换器，将 Pydantic 风格字段声明转换成标准 JSON Schema，全程不执行用户代码。
- 支持基础类型、列表、字典、Optional、Literal、嵌套模型及常用 Field 约束。
- 新增双向转换 API；数据库和 Agent 运行时继续使用原有 `output_schema`，无须迁移历史数据。
- 增加可执行语句拒绝、约束转换和 JSON/Python 往返转换测试。

## 工作流人工审批机制核查

### work_list

1. 检查工作流编辑器是否支持人工确认节点。
2. 检查审批节点暂停时的运行状态、步骤状态和恢复上下文持久化。
3. 检查批准、拒绝接口以及前端操作入口。
4. 检查 Redis Stream 审批事件和恢复订阅游标。
5. 运行现有人工审批单元测试。
6. 区分项目自研审批恢复机制与 LangGraph 原生 `interrupt/resume`。

### 核查结果

- 当前 DAG 工作流支持人工确认节点、批准、拒绝和审批意见。
- 暂停点保存在 MySQL `multi_agent_runs.context_json`，不依赖内存 Checkpoint，因此服务重启后仍可读取恢复位置。
- 批准后由后台任务从 `resume_node_id` 继续遍历；拒绝后运行状态变为 `rejected`。
- Redis Stream 发布 `approval_required`、`approval_decided` 和 `rejected` 事件，前端提供对应审批界面。
- `backend.test.test_workflow_approval` 的 3 个测试已全部通过。
- 当前实现不是 LangGraph 原生 `interrupt()`/`Command(resume=...)`，而是项目自己的业务层暂停和恢复机制。
- 后续建议为审批接口增加原子状态更新或行锁，避免并发重复审批触发重复恢复。

- 登录、Agent CRUD、模型配置和普通聊天属于必要的平台基础能力，不建议单独作为核心技术亮点。
