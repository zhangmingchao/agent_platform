# 2026-08-31 开发记录

## MongoDB Trace Span 存储升级

### 功能描述

Trace 存储改为混合架构：

- MySQL 保存 `trace_runs` 汇总、状态、用户、Agent、工作流关联、耗时和 Token 等稳定字段。
- MongoDB 保存 LLM 与 Tool 的 `trace_spans` 明细、输入输出和扩展元数据。

根据本次产品要求，MongoDB 是强依赖：连接失败时后端拒绝启动；运行期间 Span 写入失败会明确抛错，不回退写入 MySQL。

### MongoDB 本地部署

- 使用 Docker Compose 安装 MongoDB `8.0.12`。
- 容器名称：`agent-platform-mongodb`。
- 仅监听 `127.0.0.1:27017`，不对局域网公开。
- 使用 Docker Volume `agent-platform-mongodb-data` 持久化数据。
- 配置账号认证、健康检查和自动重启。

管理命令：

```bash
docker compose -f docker-compose.mongodb.yml up -d
docker compose -f docker-compose.mongodb.yml ps
docker compose -f docker-compose.mongodb.yml logs mongodb
docker compose -f docker-compose.mongodb.yml stop
```

### 应用改动

- 新增 MongoDB 连接生命周期管理，应用启动时执行 `ping` 和索引初始化。
- 应用关闭时释放 MongoDB 客户端。
- `TraceContext` 创建和完成 LLM/Tool Span 时改为读写 MongoDB。
- Trace 列表的 `span_count` 使用 MongoDB 聚合查询。
- Trace 详情从 MongoDB 读取 Span，并保持原前端字段结构。
- Trace Run 汇总继续使用 MySQL，避免影响权限关联和报表查询。
- 新增依赖 `motor>=3.6.0`。

### MongoDB 索引

- `trace_run_id + started_at`：Trace 详情调用链查询。
- `user_id + started_at`：用户维度查询。
- `workflow.run_id`：工作流运行关联查询。
- `expire_at` TTL：默认保留 90 天后自动删除。
- `legacy_mysql_id` 唯一稀疏索引：保证历史迁移可以重复执行。
