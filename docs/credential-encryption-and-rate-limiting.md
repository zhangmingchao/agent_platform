# 凭据加密与高风险接口限流

## 实现目标

本次安全升级解决三类问题：用户密码明文存储、模型 API Key 明文存储，以及登录和高风险接口缺少分布式限流。

## 密码存储方案

- 新注册和修改后的密码统一使用 Argon2id 哈希保存。
- 登录只按用户名查询用户，再在应用内验证密码哈希。
- 历史明文密码继续允许登录一次；验证成功后立即原位升级为 Argon2id 哈希。
- `users.password` 扩展为 `VARCHAR(255)`，用于保存带参数和随机盐的哈希。
- 初始化脚本不再创建默认弱口令账号。

密码哈希不可逆。系统不会保存能够还原用户密码的密钥。

## 模型 API Key 加密方案

模型 API Key 使用 AES-256-GCM 加密，密文格式为：

```text
enc:v1:<nonce + ciphertext + authentication-tag 的 URL-safe Base64>
```

每次加密生成独立 12 字节随机 Nonce，并使用固定版本化关联数据防止密文被移作其他用途。历史明文 Key 在第一次被 Agent 或连接测试读取时自动原位加密。

必须配置独立主密钥：

```bash
export MODEL_API_KEY_ENCRYPTION_KEY="$(openssl rand -base64 32 | tr '+/' '-_' | tr -d '=')"
```

注意事项：

- 主密钥不得提交到 Git，应由部署环境的 Secret Manager 注入。
- 所有实例必须使用同一密钥。
- 丢失该密钥后，已经加密的 API Key 无法恢复。
- 轮换密钥前必须先使用旧密钥解密，再使用新密钥重新加密。
- 未配置或配置错误时，涉及非空 API Key 的保存、读取会明确失败，不会降级为明文。

## 限流方案

限流使用 Redis 固定窗口和 Lua 原子计数。限流主体经过 SHA-256 后进入 Redis Key，避免用户名、IP 等原始标识直接暴露。

默认策略：

| 接口 | 主体 | 默认限制 |
|---|---|---|
| 登录 | IP | 5 分钟 10 次 |
| 登录 | 用户名 | 5 分钟 5 次 |
| 注册 | IP | 5 分钟 5 次 |
| 模型连接测试 | 用户 | 每分钟 10 次 |
| MCP 工具调试调用 | 用户 | 每分钟 30 次 |
| 流式聊天 | 用户 | 每分钟 30 次 |
| 工作流运行 | 用户 | 每分钟 10 次 |
| 工作流审批 | 用户 | 每分钟 30 次 |
| Runtime 文件上传 | 用户 | 每分钟 20 次 |
| Runtime 代码执行 | 用户 | 每分钟 10 次 |

超过限制返回 `429 Too Many Requests` 和 `Retry-After`。Redis 不可用时高风险接口返回 `503`，避免绕过安全策略。

只有服务部署在可信反向代理之后时，才能配置 `TRUST_PROXY_HEADERS=true`。否则客户端可以伪造 `X-Forwarded-For` 绕过 IP 限流。
