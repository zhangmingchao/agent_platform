# Agent 单层委托

## 使用方式

先创建具备清晰能力描述、自定义模型和所需工具的目标 Agent。编辑主 Agent，打开「允许委托」，选择同用户目标，设置每轮委托次数（默认 3，上限 10）。系统向主模型注册 `DelegateTask`，由模型按任务决定是否调用。开关表示允许，不强制每轮委托；需要明确分工时，在主 Agent 提示词里说明哪些任务交给哪个角色。

模型调用参数示例：

```json
{"agent_id": 12, "task": "分析销售下降的前三个原因，给出依据", "context": "统计周期为最近七天。输入文件 ID：已上传文件的真实 ID。"}
```

目标使用自己的模型、提示词模板、结构化输出、Skill、MCP 和已安装插件。任务及必要背景作为独立用户消息传入，主聊天历史不会自动复制。API Key 不作为委托参数。目标的返回结果作为工具结果交还主模型，主模型继续汇总并给出最终答案。子模型 Token 由目标模型配置的现有额度 Callback 计量。

## 执行边界

- 仅同用户白名单，保存和运行时均检查用户归属；删除目标后不会继续调用该目标。
- 只允许一层，子任务不注册委托工具，即使目标自身开启委托也不能再次调用。
- 每次父执行有独立预算，多次工具调用共享锁，顺序执行；下一轮重新计数。
- 子 Agent 的状态和工作目录独立，复用同一用户 Docker 容器；目录区分用于避免误混，不能视为额外容器安全隔离。
- 权限预设取保守交集：任一 safe 则 safe，任一 auto 则 auto，其余不同组合则 standard；子工具继续走统一权限流水线。当前项目高风险工具尚无通用交互审批通道，仍沿用原拒绝规则。
- 父执行的总时限包括委托等待，目标执行还受自己的总时限限制。父超时/取消传播至子协程；Python 与插件沿用现有 Worker 的取消通道。已发生的外部副作用不自动回滚。
- 子任务失败/超时返回状态供主模型调整策略；主模型拿到失败结果后仍可解释或继续执行。
- 子任务结果最多返回 20000 字符，聊天历史和事件日志保存最多 500 字符摘要；完整最终结果可在子 Trace 查看。

## 事件与追踪

父聊天只转发 `delegation_started`、`delegation_completed` 公开委托状态，子模型和工具原始事件带 `delegation_child` 标签，在父流中被过滤，避免子答案混进主答案。聊天实时显示目标、状态与摘要，成功聊天保存摘要后可刷新回看。取消或失败时以 Trace 为准。

每次子执行有独立 Trace，`trace_runs.parent_trace_run_id` 关联父 Trace；Trace 页面提供父/子入口。各 Trace 的 `total_tokens` 仅计自身模型调用，查看合计时应汇总父子记录，避免重复计数。平台聊天、外部聊天 API 和工作流节点复用委托工具；工作流发布委托事件并记录父子关系。

## 数据与代码

Agent 新字段：`allow_delegation`、`delegation_agent_ids`、`delegation_max_calls`，默认关闭；聊天增加 `delegation_results` 摘要列。启动初始化自动增加缺失列，不要求清空旧表。

实体：`backend/models/delegation.py`。工具与预算：`backend/core/delegation_tools.py`。执行服务：`backend/services/delegation_service.py`。开发方案和验证记录在 `work_list/2026-10-23.md`。
